# Lib to Dll — Documentation

`lib-to-dll` turns a **static library (`.lib`) built with Visual C++ into a
DLL**, with its import library, without changing the code or the build of
the library. It is a Windows command line tool that drives the Visual C++
tools (`lib.exe`, `link.exe`) and
[xyo-coff-to-def](https://github.com/g-stefan/xyo-coff-to-def).

```
lib-to-dll --mode WIN64 zlib.lib
```

```
before                 after
zlib.lib  (static)     zlib.static.lib   the original static library, kept
                       zlib.dll          the DLL, every object of the library inside
                       zlib.lib          import library of zlib.dll
```

Programs that linked `zlib.lib` link the same file name and now use
`zlib.dll`.

## Why it exists

Many libraries (third-party code in the `vendor-*` projects, small C
libraries) only have a build for a static library, or their DLL build needs
export macros (`__declspec(dllexport)`) on every function. `lib-to-dll`
makes the DLL from the compiled objects instead:

| Problem | What `lib-to-dll` does |
|---------|------------------------|
| The library has no DLL build | takes the objects out of the `.lib` and links them as a DLL |
| No `__declspec(dllexport)` in the code | exports every public symbol of the objects (`xyo-coff-to-def` writes the DEF file) |
| Only some functions must be exported | uses your `in.def` next to the library, if there is one |
| The DLL needs other libraries | links the extra `.lib` / `.obj` files given after the library |
| Programs must keep linking `in.lib` | writes the import library as `in.lib`, the static one is kept as `in.static.lib` |
| The DLL must not need the Visual C++ runtime DLLs | `--static-crt` links the static C runtime |

## How it works, at a glance

```
in.lib (static)
  │  move to in.static.lib
  │  lib /list                      member names
  │  lib /extract (each member)     in.obj\*.obj
  │  xyo-coff-to-def                in.dll.def (or your in.def)
  │  link /dll @in.rsp              in.dll + in.lib (import library)
  ▼  remove temporary files         in.obj\, in.lst, in.rsp, in.exp, in.dll.def
in.dll, in.lib (import), in.static.lib
```
